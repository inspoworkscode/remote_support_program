What you are doing, and what you are not

The website theremotesupportprogram.com is hosted on xneelo shared hosting, managed through a control panel called konsoleH. There is one page on it today. You are replacing that page with a newer one.

That is nearly the whole job. There is one setting to change at the end, in step 6, and it is named there. Apart from that you are not touching DNS, email, or any other setting. If a screen you are on is about anything else, you are in the wrong place — back out.

Do not rename the file

It must be uploaded as index.html, exactly, in lower case. A web server looks for that precise name. Index.html, index.htm or index (1).html will not be served, and the site will look unchanged or show a list of files instead.

Check the name before you upload — browsers often add (1) to a downloaded file when one of the same name already exists.

1

Sign in to konsoleH konsoleh.xneelo.co.za

Open https://konsoleh.xneelo.co.za and sign in with the details Clint gave you.

Once in, select the domain theremotesupportprogram.com. Some accounts list several domains and open on a summary page; others go straight into the one domain. Either is normal — you just need to be looking at this domain before the next step.

If you cannot sign in

Stop and go back to Clint. There are two separate xneelo systems — konsoleH for hosting and email, and a different one for cloud servers. Only konsoleH is used here, and logins for one do not work on the other.

2

Open the file manager in konsoleH

Look for File Manager under the web hosting section of the menu. konsoleH has been redesigned more than once, so it may sit under a heading such as Web, Hosting or Tools. It is the option that lets you browse folders and upload files.

Now open the folder called public_html. Everything the public website serves lives in that folder, and nothing outside it is part of the website.

If you cannot find the file manager

Use FTP instead — it does the same job. The server is www40.cpt3.host-h.net, and FTP usernames and passwords are created and shown in konsoleH under FTP Users. Connect with FileZilla or any FTP client, then open public_html and carry on from step 3.

3

Move the old page out of the way in public_html

Look in public_html for a file called index.html, and also one called index.htm. One or both will be there.

Rename each one you find by adding .old to the end, so index.html becomes index.html.old. Most file managers offer Rename when you right-click a file, or from a menu next to it.

Renaming rather than deleting means the old page can be put straight back if anything is wrong, which is worth ten seconds.

This step is the one people skip

If the old index.html is still there when you upload the new one, one of two things happens: the upload is refused, or it overwrites without warning. If it is refused, the website carries on showing the old page and it looks as though the upload did nothing.

Leave everything else alone

Do not delete any other file or folder in public_html, even if it looks unused. If the folder contains things you were not expecting, that is fine — carry on.

4

Upload the new page into public_html

Use the Upload button in the file manager and choose the index.html Clint gave you. Make sure you are still inside public_html when you do it — not in the folder above it.

When it finishes, you should see index.html listed, roughly 23 KB in size, with today's date.

Check the name one more time

If it uploaded as index (1).html or anything other than index.html, rename it now. This is the single most common reason the site does not change.

5

Check it worked in a browser

Open the website:

https://theremotesupportprogram.com

You should see a dark navy page headed “Remote support that carries your brand”, with purple buttons, and further down a pricing section showing R500 and four region buttons — South Africa, US & Canada, United Kingdom, Europe.

How to tell the new page from the old one

The old page is also dark navy, which makes them very easy to confuse. Two reliable differences:

  • The new page has a pricing section with R500 and four region buttons. The old one has no pricing at all.
  • The new page's email address is queries@theremotesupportprogram.com. The old one says info@.

If you see no pricing, or an info@ address, you are still looking at the old page. Go back to step 3 and check the rename and the file name.

If the browser shows an old version

Press Ctrl + F5 to force a reload, or open the site in a private window. Browsers hold on to a page they have seen before, which can make a correct upload look as though it did nothing.

You can also check the site directly on the hosting server, which bypasses caching entirely: http://theremotesupportprogram.com.www40.cpt3.host-h.net

6

Switch on Force HTTPS in konsoleH

The site has a valid security certificate, so https:// works. Visitors who type the address without it still arrive on the unencrypted http:// version, and this setting sends them to the secure one automatically.

In konsoleH, find the Web Server Config settings for the domain and turn on Force HTTPS (it may be called Redirect to HTTPS or SSL redirect). Save.

Then check it. Type the address with http:// deliberately:

http://theremotesupportprogram.com

The browser should jump to https:// on its own, with a padlock showing.

Do this last, and only if step 5 worked

If https://theremotesupportprogram.com did not load cleanly with a padlock in step 5, stop and tell Clint. Forcing HTTPS when the certificate is not working takes the website off the internet completely, and it is not obvious from inside konsoleH that it has happened.

If the site stops loading after you change this, switch the setting back off. That undoes it immediately.

Hand back to Clint

Tell him these four things

  • The new page is live on the interim address, and you can see the pricing section with R500 and the four region buttons.
  • What the old file was renamed to, and that it is still in public_html.
  • That https://theremotesupportprogram.com loads with a padlock, and that typing
    http:// now jumps to it.
  • Anything in public_html that looked unexpected. Do not act on it — just say what you saw.

If something goes wrong

Putting it back

If the new page is wrong in any way, rename index.html to index.html.new and rename index.html.old back to index.html. The site returns to exactly what it was, immediately.
